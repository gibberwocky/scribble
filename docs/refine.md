# refine

## Purpose

The `refine` module performs recursive subclustering of selected clusters identified during the evaluation stage.

Clusters flagged for further investigation are isolated, reclustered, assessed for stability, and assigned new refinement labels. Marker genes, reassignment statistics, lineage relationships, and refinement summaries are generated automatically.

The output is a hierarchically refined AnnData object that supports more granular biological annotation.

## Inputs

- Clustered AnnData object from the `cluster` module
- Decision table generated by the `evaluate` module
- Harmony embedding and clustering metadata
- Original count matrix stored in the AnnData object

## Outputs

- Refined AnnData object
- Refined cluster marker workbook
- Refinement report
- Cluster reassignment table
- Refined cluster UMAP
- Module manifest

## Main Functions

- Import cluster refinement decisions
- Restore full count matrices prior to subclustering
- Perform recursive reclustering of selected clusters
- Recalculate PCA, Harmony integration, neighbours, UMAP, and Leiden clustering
- Assess cluster stability and reassignment behaviour
- Generate marker genes for each refined cluster
- Track cluster lineage relationships across refinement levels
- Produce refinement summaries and diagnostic reports
- Create a curated refined clustering hierarchy

## Parameters

### Required Parameters

| Parameter | Description |
|------------|-------------|
| `--project_dir` | Root Scribble project directory. |
| `--input` | Clustered AnnData object, typically the output from the `cluster` module. |
| `--decisions` | TSV file generated by the `evaluate` module containing cluster refinement decisions. |

### Recursive Refinement

| Parameter | Default | Description |
|------------|----------|-------------|
| `--max_refine_depth` | 2 | Maximum recursive refinement depth. |
| `--min_cells_per_group` | 200 | Minimum cells required before a cluster can be refined. |
| `--min_cells_per_cluster` | 50 | Minimum cells required for a refined cluster to be retained. Smaller clusters are collapsed back into their parent. |

### Highly Variable Gene Selection

| Parameter | Default | Description |
|------------|----------|-------------|
| `--hvgs` | 3000 | Number of highly variable genes used during refinement. |
| `--batch` | sample | Batch annotation used for HVG selection and Harmony integration. |
| `--min_cells_per_gene` | 3 | Minimum number of cells expressing a gene before it is retained. |

### Dimensionality Reduction

| Parameter | Default | Description |
|------------|----------|-------------|
| `--npcs` | 50 | Number of principal components to calculate. |
| `--neighbors` | 15 | Number of neighbours used for graph construction. |
| `--theta` | 1 | Harmony batch-correction parameter. |

### Clustering

| Parameter | Default | Description |
|------------|----------|-------------|
| `--resolution` | 0.5 | Leiden clustering resolution when automatic optimisation is disabled. |
| `--auto_resolution` | False | Automatically optimise Leiden resolution. |
| `--res_min` | 0.2 | Minimum resolution tested during optimisation. |
| `--res_max` | 2.0 | Maximum resolution tested during optimisation. |
| `--res_steps` | 10 | Number of resolutions evaluated in optimisation. |
| `--fine_width` | 0.2 | Width of secondary fine-scale optimisation. |

### Stability Analysis

| Parameter | Default | Description |
|------------|----------|-------------|
| `--n_repeats` | 10 | Number of repeated clustering runs used to estimate stability. |
| `--stability_threshold` | 0.95 | Clusters above this stability threshold are considered sufficiently resolved and are not refined further. |

### Marker Evaluation

| Parameter | Default | Description |
|------------|----------|-------------|
| `--nmarkers` | 100 | Number of marker genes exported per cluster. |
| `--marker_strength_threshold` | 1.0 | Mean log fold change threshold used to determine whether cluster markers are already sufficiently distinct. |

### Integration Control

| Parameter | Default | Description |
|------------|----------|-------------|
| `--skip_integration` | False | Skip Harmony integration and cluster directly in PCA space. |
| `--no_scale` | False | Skip scaling before PCA. |

### Reassignment Analysis

| Parameter | Default | Description |
|------------|----------|-------------|
| `--dominant_reassignment_threshold` | 0.05 | Minimum reassignment fraction reported in summaries. |
| `--reassignment_display_threshold` | 0.01 | Minimum reassignment fraction displayed in reassignment tables. |
| `--high_reassignment` | 0.30 | Threshold used to flag candidate merges. |

### Saved Parameter Behaviour

| Parameter | Default | Description |
|------------|----------|-------------|
| `--ignore_saved_params` | False | Ignore clustering parameters stored in the AnnData object and use CLI values instead. |

### Reproducibility

| Parameter | Default | Description |
|------------|----------|-------------|
| `--manifest` | None | Load parameters from a previous Scribble manifest file. |

### Notes

- Refinement is recursive and can generate multiple levels of subclusters.
- Full count matrices are restored prior to each refinement step so that marker detection is performed on the complete gene space.
- Each refinement step repeats HVG selection, PCA, Harmony integration, neighbour graph construction, and Leiden clustering.
- Marker genes are identified using the Wilcoxon rank-sum test.
- Cluster lineage relationships are tracked automatically and recorded in the refinement report.
- Refined clusters are assigned global labels (`R1`, `R2`, `R3`, ...), allowing cluster identities to remain unique across refinement rounds.
